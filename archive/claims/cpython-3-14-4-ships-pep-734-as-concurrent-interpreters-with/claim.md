CPython 3.14.4 ships PEP 734 as `concurrent.interpreters` with API {`create`, `Interpreter`, `Queue`, `create_queue`, `is_shareable`, `NotShareableError`, `ExecutionFailed`, ...}. Subinterpreters are fully isolated (own module objects and globals; `exec` in a subinterpreter cannot touch the caller's namespace) and cost single-digit milliseconds to create. Cross-interpreter shareable data (`prepare_main`/`is_shareable`) covers `int`, `float`, `str`, `bytes`, `bool`, `None`, and tuples of shareables — but not `list`, `dict`, or `set` (`NotShareableError`). `Interpreter.call(fn)` returns the function's value but accepts only *stateless* functions: a function with closure cells raises `NotShareableError` ("only stateless functions are shareable"), while a no-free-variable lambda works; `is_shareable(fn)` is `False` even for callable functions, since `call` uses a separate mechanism. The key footgun: calling a function defined in `__main__` makes the subinterpreter **re-execute the entire `__main__` script** (multiprocessing-spawn-style), so the called function sees freshly re-initialized module globals, not the caller's current values — a global mutated to 999 after definition still reads as its top-of-script value 1 inside the call. Uncaught exceptions in a subinterpreter surface in the caller as `ExecutionFailed`.
