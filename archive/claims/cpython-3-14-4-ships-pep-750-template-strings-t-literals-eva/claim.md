CPython 3.14.4 ships PEP 750 template strings: `t"..."` literals evaluate eagerly (interpolation expressions run at literal-evaluation time, raising e.g. `NameError` immediately) to `string.templatelib.Template`, whose public module surface is {`Template`, `Interpolation`, `convert`}. A Template exposes `.strings` (tuple of static parts, always `len(interpolations)+1`, so `t"x={1+1}"` gives `('x=', '')`), `.interpolations` (tuple of `Interpolation(value, expression, conversion, format_spec)` — for `{1+1}` that is `(2, '1+1', None, '')`; `{42!r:>5}` yields `conversion='r'`, `format_spec='>5'`), and `.values` (tuple of interpolation values). Iterating a Template interleaves parts but skips empty static strings. `Template + Template` merges (adjacent strings joined), while `Template + str` and `str + Template` both raise `TypeError`; implicit literal concatenation `t"a" t"b"` merges at compile time, but mixing t-strings with f-strings/str literals is a `SyntaxError` ("cannot mix t-string literals with string or bytes literals"). `str(template)` does not render the interpolated values — it returns a descriptive `Template(strings=..., interpolations=...)` repr, not the formatted string.
