CPython 3.14.4's `concurrent.interpreters` passes objects between interpreters in two tiers. Tier 1, true sharing: `is_shareable()` returns True for str, bytes, int, float, bool, None, tuple (even tuples containing unshareable items like `(1, [2])`), memoryview, and Queue; these cross a `Queue` without pickling, and memoryview shares the underlying buffer — mutating the source bytearray after `put()` is visible in the object returned by `get()`. Tier 2, pickle fallback: unshareable objects (list, dict, set, custom instances) still succeed in `Queue.put` — their `__reduce__` is invoked (the fallback is surfaced by the `unbounditems` parameter on `create_queue`/`put`) — while shareable objects skip pickling entirely. For `Interpreter.call`: stateless functions (no closure, no global references — including lambdas) are shared directly; a function that references module globals is pickled by reference, which forces the target interpreter to re-import `__main__` in the same process (module-level code re-executes as a fake `__main__`, same pid), so the callee sees a fresh re-import snapshot of globals, not the caller's live values (caller sets `GLOBAL_VAL = 99`, callee still returns the module-level 42); closures raise `NotShareableError: only stateless functions are shareable`. The apparent nondeterminism of unguarded scripts is fully explained by this re-execution of `__main__`.
