CPython 3.14.4 replaced the classic three-generation GC with an incremental collector, and the observable API semantics changed accordingly: `gc.get_threshold()` defaults to `(2000, 10, 0)` (third slot dead); `gc.get_count()[0]` is a *net* survivor count (decremented on dealloc), so allocate-then-free churn never crosses the threshold and triggers zero automatic collections; when kept-alive allocations do cross it, every automatic collection is reported to `gc.callbacks` with `generation: 1` — never 0 or 2 — because each is an "increment" scanning the young space plus a slice of the old space; `gc.get_stats()[0]['collections']` never advances (stays 0), `stats[1]['collections']` ticks only when a full incremental pass over the old space completes (so callback events outnumber the stat, e.g. 60 events → ~14 ticks), and `stats[2]` advances only on explicit full collection; these automatic increments do reap unreachable cycles without any explicit `gc.collect()`; explicit `gc.collect(g)` fires one callback event tagged `generation: g`, with `collect(0)` incrementing `stats[0]` and `collect(2)` incrementing `stats[2]`.
